# MLOps Lab 2 — Airflow lab 1

## Overview

This lab implements an automated machine learning pipeline using **Apache Airflow 2.9.2**, Docker Compose, and K-Means clustering to segment wholesale customers based on their annual spending patterns with modifications to the dataset, DAG structure, data validation, model selection, and evaluation.

Additional directories such as `logs/`, `config/`, `plugins/`, and `working_data/models/` are created locally as needed.

## Modifications to the Original Lab

The following changes were made to the original Airflow pipeline:

1. **Dataset:** Replaced the original dataset with the [UCI Wholesale Customers dataset](https://archive.ics.uci.edu/dataset/292/wholesale+customers), containing 440 customer records.

2. **Data validation:** Added a separate `validate_data_task` to check required columns, missing values, empty datasets, and invalid negative spending values before preprocessing.

3. **DAG structure:** Modified the original workflow to include five dependent tasks, ensuring that validation is completed before preprocessing and model training.

4. **Preprocessing:** Selected six spending features and applied MinMaxScaler for normalization.

5. **Model selection:** Used K-Means clustering and the elbow method with KneeLocator to identify the optimal number of clusters and save the selected model.

6. **Model evaluation:** Added silhouette-score evaluation to measure clustering quality.

7. **Error handling:** Configured task retries to improve pipeline reliability.

8. **Persistent storage:** Added a Docker volume mount to store the trained model outside the Airflow containers.

## Airflow Pipeline

```text
load_data_task
      ↓
validate_data_task
      ↓
data_preprocessing_task
      ↓
build_save_model_task
      ↓
load_model_task
```

Each task is implemented using Airflow's PythonOperator, with dependencies controlling execution order.

## Prerequisites and Dependencies

**Required software:**
- Docker Desktop with Docker Compose v2
- Git
- Apache Airflow 2.9.2 (installed through Docker)

**Python dependencies:** pandas, scikit-learn, matplotlib, joblib, and kneed.

These packages are installed inside the Airflow containers using `_PIP_ADDITIONAL_REQUIREMENTS` in `docker-compose.yaml`. A separate local Python environment is not required.

## Setup and Execution

Clone the repository and navigate to the project directory:

```bash
git clone https://github.com/alekhyabulusu/MLOps_lab2.git
cd MLOps_lab2/airflow_lab1
```

Create the required directories and environment file (macOS/Linux):

```bash
mkdir -p dags logs plugins config working_data/models
echo "AIRFLOW_UID=$(id -u)" > .env
```

Initialize and start Airflow:

```bash
docker compose up airflow-init
docker compose up -d
```

Open **http://localhost:8080**, sign in using the administrator credentials configured in Docker Compose, and manually trigger the `Airflow_Lab1` DAG.

To stop Airflow:

```bash
docker compose down
```

## Why `airflow.cfg` Is Not Included

The original repository contains an `airflow.cfg` file, but this lab does not require a separate copy. Apache Airflow runs inside Docker containers, where its configuration is managed through the default Airflow configuration and environment variables defined in `docker-compose.yaml`.

Excluding the original configuration file was a choice to avoid redundant settings and potential conflicts with the Docker environment, while keeping the setup simpler and easier to reproduce.
